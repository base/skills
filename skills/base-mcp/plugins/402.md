# 402 Plugin

> [!IMPORTANT]
> Run Base MCP onboarding first (see `SKILL.md`). There is no account or API key to set up here — every endpoint answers `402` with its own price, and Base MCP pays it. Read the price from the challenge before paying; never hardcode one from this file.

## Overview

[402.com.tr](https://402.com.tr) is a catalogue of read-only Base intelligence endpoints, each priced per call over x402 and settled in USDC on Base mainnet. There are no accounts, no API keys and no rate-limit tiers: an unpaid `GET` returns a `402` carrying the price and an `accepts` array, and the same `GET` with payment returns the answer. This plugin reads those HTTP endpoints; it builds no calldata and submits no onchain writes of its own — the only transaction involved is the x402 payment, which Base MCP handles through `initiate_x402_request` / `complete_x402_request`.

Two things here are hard to get anywhere else. **Tokenized-stock entitlements:** Coinbase's tokenized equities are B20 Asset tokens, and B20 does not apply `multiplier()` to `balanceOf()` — so the number a wallet, indexer or contract reads is not the number of shares owned. That stopped being theoretical on 14 September 2026, when GOOGLc's multiplier moved `1.0 → 1.000377118676784179` in block 51310619 while `balanceOf` and `totalSupply` both stayed put. **B20 authenticity:** a scammer can deploy an ordinary contract at a vanity `0xb200…` address and fake the entire B20 read surface, so membership is decided by the on-chain transfer-policy administrator rather than by an address list.

## Surface Routing

Every endpoint is a `GET` with query parameters and no authentication headers, which means the chat-only path works without the usual compromises — there is no key to paste and no POST body to construct.

| Capability | HTTP-capable harnesses (Claude Code, Codex, Cursor) | Chat-only (Claude.ai, ChatGPT) |
| --- | --- | --- |
| Read a price (unpaid `402`) | Harness HTTP tool. | Base MCP `web_request` if `402.com.tr` is allowlisted; otherwise the GET-only user-paste fallback. |
| Free catalogue and board (`/api/catalog`, `/api/stocks`) | Harness HTTP tool. | Same; these need no payment at all. |
| Paid call | Harness HTTP tool, with the `X-PAYMENT` header from Base MCP. | Base MCP `web_request` if allowlisted **and** custom headers are supported; otherwise stop and tell the user this needs an HTTP-capable harness. Do not ask the user to paste a payment header into chat. |

The full decision tree and the GET-only constraint on consumer surfaces live in [custom-plugins.md](../references/custom-plugins.md).

## Endpoints

Base URL `https://402.com.tr`. Prices below are what the catalogue published at the time of writing — always read the live price from the `402` challenge, never from this table.

### Free — no payment, no key

| Endpoint | Returns |
| --- | --- |
| `GET /api/catalog` | Every endpoint with its price, parameters and a runnable example value per parameter. The machine-readable source of truth; `/.well-known/x402` serves the same document. |
| `GET /api/stocks` | Live board of Coinbase's tokenized equities: multiplier, supply, issuance and transfer-policy state for each. |

### Paid

| Endpoint | Price | Parameters | Returns |
| --- | --- | --- | --- |
| `GET /api/x402/stock-position` | $0.03 | `wallet` (required) | Per-holding `reportedShares` (what `balanceOf` says) beside `entitledShares` (what is actually owned), plus a `coverage` block naming which venues are **not** counted. |
| `GET /api/x402/pre-trade-gate` | $0.10 | `address` (required), `amountUsd` | One `GO` / `HOLD` / `STOP` verdict over token risk, sellability, price impact and deployer reputation, with an auditable receipt. Cheaper than the four checks separately. |
| `GET /api/x402/b20-authenticity` | $0.02 | `address` (required) | Whether a `0xb200…` address is a real B20 issuance or a lookalike, decided by the transfer-policy administrator on chain. |
| `GET /api/x402/b20-info` | $0.02 | `address` (required) | B20 profile from the precompile: variant, name, symbol, decimals, supply, cap, transfer policies. |
| `GET /api/x402/token-risk` | $0.03 | `address` (required) | Risk score and flags — ERC-20 conformance, ownership renounce, upgradeable proxy — computed live from Base. |
| `GET /api/x402/sellability` | $0.08 | `address` (required), `size` | The honeypot question three ways: security simulation, a live transfer simulation, and sell/buy tax. |
| `GET /api/x402/address-trust` | $0.03 | `address` (required) | Coinbase's on-chain verification for an address, read from the EAS attestation by `verifications.coinbase.eth`. |
| `GET /api/x402/buy-credits` | tier | `tier` — `0.25`, `1`, `5`, `20` | One settlement mints a bearer credit token; send it as `x-credit-token` on later calls and each debits its price with no per-call signature. For agents making many calls in a session. |

The payment wall comes before input validation, so a malformed request without payment still answers `402`. Once paid, a malformed input answers `400` and **is not settled** — the buyer is never charged for an error. A refusal, meaning a low-confidence answer because an upstream feed was unavailable, answers `502` and is likewise never billed.

## Orchestration

1. **Establish the wallet.** Base MCP `get_wallets` gives the address that will pay. `stock-position` also takes a `wallet` parameter — these are independent: you may read any wallet's entitlement while paying from your own.
2. **Read the price.** `GET` the endpoint with its parameters and no payment. Expect `402` with a body containing `resource`, a `sample` preview of the shape you are buying, and an `accepts` array. Each `accepts` entry carries `scheme`, `network`, `amount`, `asset`, `payTo` and `maxTimeoutSeconds`.
3. **Check before paying.** Confirm `network` is `eip155:8453` and that `amount` matches what you told the user. Use the `sample` to confirm the endpoint answers the question that was actually asked — it is a redacted preview of a real response, and it costs nothing.
4. **Pay.** Hand the chosen `accepts` entry to Base MCP `initiate_x402_request`, then `complete_x402_request`. Pay exactly the returned `payTo`, `asset` and `amount`; never substitute values from this file.
5. **Repeat the request** with the resulting `X-PAYMENT` header. The answer arrives as `{ service, builderCode, data, related }` — read the payload from `data`, not from the top level. `data.receipt` carries `endpoint`, `inputHash` and `policyVersion`, so identical inputs are provably the same call and can be cached or deduplicated on that hash.
6. **For many calls in one session**, buy credits once at step 4 and send `x-credit-token` on every later request instead of settling each one.

### Reading a tokenized-stock position

Ask `/api/x402/stock-position` and compare the two numbers it returns. If `entitledShares` differs from `reportedShares`, a corporate action has been applied and every cached balance for that token is stale — say so explicitly rather than reporting one number. Check `coverage` before calling a total a position: wallet balances are counted, while pool, vault and lending exposure is declared as **not** counted rather than silently returned as zero.

## Submission

Base MCP submission tool: **`initiate_x402_request` / `complete_x402_request`** — the x402 payment path. This plugin produces no unsigned calls, so `send_calls` and `swap` are never used, and there is no message to `sign`.

Map the chosen `accepts` entry straight through: `payTo` → recipient, `asset` → token, `amount` → amount, `network` (`eip155:8453`) → Base mainnet. Settlement is EIP-3009 `transferWithAuthorization` on Circle USDC at `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913` (EIP-712 name `USDC`, version `2`). The facilitator submits and pays gas; the payer needs USDC but no ETH.

Any write tool returning an approval URL follows [approval-mode.md](../references/approval-mode.md).

## Example Prompts

**"Does this wallet actually hold what its balance says on the tokenized stocks?"**
1. `GET /api/x402/stock-position?wallet=<address>` → read the `402`, confirm `amount` and `eip155:8453`.
2. Pay via `initiate_x402_request` / `complete_x402_request`, repeat with `X-PAYMENT`.
3. Report `reportedShares` beside `entitledShares` for each holding; call out any where they differ.
4. State the `coverage` caveat before calling the total a full position.

**"Is it safe to buy this Base token?"**
1. `GET /api/x402/pre-trade-gate?address=<token>&amountUsd=<size>`.
2. Pay, then relay the `GO` / `HOLD` / `STOP` verdict with the reasons behind it.
3. On `HOLD` or `STOP`, do not proceed to a swap without explicit user confirmation.

**"Someone sent me a token at 0xb200… — is it a real Coinbase B20?"**
1. `GET /api/x402/b20-authenticity?address=<token>` first. A vanity address proves nothing.
2. If authentic, `GET /api/x402/b20-info` for the profile.
3. If not, say plainly that the B20 read surface is forged and do not read further values from it.

**"What can I buy here?"** (chat-only, no payment)
1. `GET /api/catalog` — free, needs no key, and each parameter carries a runnable example value.
2. Summarise the endpoints that match the user's question and quote their prices from the document.

## Risks & Warnings

- **irreversible** — an x402 settlement cannot be undone. Read `amount` and `payTo` from the live `402` challenge and confirm the figure with the user before paying; never pay a price hardcoded from this file, and never substitute a different asset for the one quoted. Buying credits commits the whole tier amount up front — say the amount out loud first.
- **Read-only, and bounded.** Every endpoint here reads; none of them trade, hold funds or move a user's tokens. Answers are on-chain and third-party data, not financial advice, and `stock-position` reports a wallet's entitlement — it does not value it.
- **Do not present `balanceOf` as a share count** for Coinbase's tokenized equities, whether it came from this plugin or elsewhere. That is the specific error `stock-position` exists to catch.

## Notes

- Base mainnet only (chainId `8453`). The `accepts` array carries exactly one network; a challenge offering more than one would not be from this service.
- Every endpoint is a `GET`. There are no POST bodies, no cookies and no auth headers, so the GET-only chat-surface fallback works for reads.
- One free call per IP per day is available on eligible endpoints, and it is **opt-in**: add `?free=1`. Without it a bare request returns the `402` challenge, which is what keeps the endpoint discoverable.
- `/.well-known/x402`, `/.well-known/x402.json` and `/api/catalog` are the same document. Parameter examples in it are runnable values, not placeholders.
- USDC on Base: `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`, 6 decimals, EIP-3009 with a 300-second authorization window.
- The tokenized-stock finding is documented with block numbers and the commands to re-read it at <https://402.com.tr/stocks/first-corporate-action>.
